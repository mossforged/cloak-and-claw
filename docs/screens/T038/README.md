# T038: v3 planted feet in the hop, jump attack and kick

**Cause.** All three moves use keys marked `aloft` (off the floor). While an aloft key shows, render/rig.js skips the floor rule. The fighter stays at z 0, though: the hop is posed with the body raised, not jumped in the sim.
- **Dodge hop and jump attack:** the aloft key turns on at once (it is a swap), but its height blends in over a few frames. On the take-off and landing frames the body is still crouched at floor height with no floor rule, so the feet sink. Dodge hop frames 8 and 29: far foot 22.8 px below its line. Jump attack frame 46: 23.4 px below. The following frames also sink the raised feet 4-23 px below the floor; the old table didn't count those because the foot's lift is over 0.5.
- **Kick:** the wind-up and strike keys are aloft so the kicking leg stays up, which also leaves the standing far toe as posed: 10-11 px above its line for 34 frames.
- No joint was at a limit in those frames because the limit solve never ran on them.

**Fix** (render/floor.js `aloftInLimits`, only on rigs with joint limits, so the old rat is unchanged). In an aloft key on the ground:
- a planted foot (lift under 0.5 px, data/limit-solve.js `planted`) goes onto its line with the T035 r2 limit solve;
- a raised foot that would sink below the floor stops on it;
- any other foot stays as posed.

**Table.** Planted feet per clip, before / after. Generated by `node tools/v3-retarget.mjs`; full tables in `before.md` and `retarget.md`. The tool now also counts aloft frames and measures the drawn lean, so `before` reads slightly differently from T035's (e.g. jump attack 23.4, not 23.1). Bold = changed.
