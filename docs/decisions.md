# Decisions

Append-only. A change is a new line that supersedes an older one (say which). Newest at the bottom.

- 2026-10-13 Genre: belt-scroller beat 'em up (not a flat side-scroller), inspired by Golden Axe, the D&D arcade games and River City Ransom (RPG growth). It is the user's animation-experiment project; turn-based projects avoid animation.
- 2026-10-13 Setting: the user's animal world (Tales of Cloak & Claw). Art from the user's cartoon art bible (29 images); cartoon chosen because it is easier to generate consistently and to rig.
- 2026-10-13 Stack: plain JS + canvas 2D, no engine, no build step.
- 2026-10-13 First content: Mouse Fighter (hero), Rat Raider (enemy), Harbor Market (single-screen arena). More heroes with distinct move sets later, not yet.
- 2026-10-13 Animation path: standees first (stage 1), then a cutout rig (stage 3). Pose swaps are the fallback if the rig disappoints.
- 2026-10-13 Fairness: at most 1 enemy attacks at a time (`RULES.maxAttackers`), with a telegraphed windup the player can interrupt.
- 2026-10-13 Repo `mossforged/cloak-and-claw`, public, GitHub Pages on. Commits use the anonymous handle only.
- 2026-10-15 Workflow: a lead chat writes task packets and reviews; Claude Code builds code; Codex builds art; the user plays and answers gates. One clone per builder on the Mac.
- 2026-10-15 Tunable data stays in `src/data/` (not a top-level `data/`) so browser imports need no path tricks.
- 2026-10-15 Art flow: the art builder delivers to `assets/source/<ID>-<slug>/`; the code builder keys/trims into `assets/art/` and wires data. No Git LFS for now (art is small; revisit if sources pass ~200 MB).
- 2026-10-15 ASSUMPTION (lead, needs the user's yes): the four design pillars in `docs/handoffs/game-brief.md`.
- 2026-10-14 Title: the game is called Tales of Cloak & Claw (user).
- 2026-10-14 Design pillars confirmed by the user as written in docs/handoffs/game-brief.md (supersedes the 2026-10-15 ASSUMPTION line).
- 2026-10-14 Run structure: B first (arcade run with River City Ransom-style growth: coins, food, shop between stages), later grow into C (branching path map + boon choices) if runs feel samey. (User, from the genre study.)
- 2026-10-14 Defence: depends on the hero; default is a **block** (Mouse Fighter: shield block; a timed parry is a possible later layer).
- 2026-10-14 Grabs and throws: yes.
- 2026-10-14 Floor weapons and breakables: yes. The user loves floor weapons and enemies dropping their weapons; breakable crates hold food.
- 2026-10-14 Combos: keep simple for now (no juggles).
- 2026-10-14 Death: lives (arcade style) for now; may be rethought if we go roguelite.
- 2026-10-14 Gate tags are created by a GitHub Action from docs/tags.txt, because the lead's cloud session cannot push tags.
- 2026-10-14 Rat Raider swing windup 22 -> ~34 frames so a warned player can step out of the lane (user confirmed in the lab); lunge reduced to 1.2 (lead). Packet T004.
- 2026-10-14 Characters are drawn in **three-quarter view toward the camera** (about 30 degrees, like the art bible standees), not pure profile. Supersedes "side view" in the style contract. (User raised it; genre practice; user deferred to the lead.)
- 2026-10-14 Cutout rigs approved as the animation approach (Stage 3 question answered yes by the user). Big swings and expressions use **part swaps** (alternate drawings of a part switched at key moments, as Vanillaware does), not more joints.
- 2026-10-14 Stage art will be briefed to a target belt depth (set the gameplay depth first, then make the art match), starting with layered stages in Stage 5. Harbor Market keeps a 63 px belt for now. (User.)
- 2026-10-14 Target belt depth: about **120 px** (about 0.9x character height, about 4 lanes at depthHit 16), tried by the user in the lab. "Might be a bit much right now", but right for bigger crowds, a companion/pet and a party of up to three players. Stage art (Stage 5) is briefed to this depth. Harbor Market stays 63 px until then.
- 2026-10-14 The tuning lab is a core tool: keep extending it (every new system gets lab sliders and test toggles). (User: "pretty amazing... we should continue to use that and develop it.")
- 2026-10-14 Clarifies the lab line above: every new system gets lab sliders as an **option**, but builders ship sensible, tested defaults that work without the user tuning anything. Only feel questions the packet names go to the user. (User: "Don't assume that everything needs me to go in there and mess around with it.")
- 2026-10-15 Enemy roster is built as an assembly line: **body x colour variant x weapon kit x gear layer**. A weapon kit = weapon image + grip type (one-hand / two-hand / bow) + moves (pose data) + AI params. Each body gets a small set of hand-grip parts once (closed grip on both hands, string-pinch hand for bows); then a new weapon is usually one image. Gear layers (helmets, armour, hoods) are overlay parts. A new silhouette (brute, hunched sneak) still needs a new torso. Held weapons use the same system as floor weapons (A003), so fighters can pick them up. (User's idea; lead's design.)
- 2026-10-15 `docs/design/lessons.md` is the standing checklist of lessons from the studies; the lead checks packets against it.
- 2026-10-15 Keep the on-screen build label (BUILD in src/config.js, shown under the KO counter): the code builder updates it per task so the user can see which version is running. (User request.)
- 2026-10-15 Grab is a button (H / gamepad Y), never automatic on walking into an enemy; reach 75 px, depth 16. Supersedes T009's walk-in grab. (User, during T009.)
- 2026-10-15 A007 Harbor Market layers approved by the user (keeps the market look; 120 px floor feels right). Import rules: one uniform scale per layer then crop (no vertical squash), floor dimmed slightly so fighters read, segment joins covered by foreground props placed in data. First scrolling stage is T013, added as a new stage beside the arena.
- 2026-10-15 Jump squat: mode A (a 4-frame crouch in the sim before take-off; a hit during it cancels the jump). User's pick after an in-game A/B test (T014).
- 2026-10-15 Rat Raider look: rig parts are redrawn **from the art-bible standee** (stocky, thick limbs, big round ears, wide crouch), not a newly designed rat (A009). A004/A005 drew a taller, rangier rat and code thickening (T011 variant C) couldn't close the gap. Enemies stay cutout rigs (pose-swap standees not chosen). Head shape (faithful standee vs slightly rattier) is the user's pick from A009's review. (User agreed with the lead.)
- 2026-10-15 T011 merged with the stopgap rat look; the spear rat, bow rat, arrows and generic weapon kits stand. (User.)
- 2026-10-16 Rig standard purpose agreed (user): faithful to the approved art; modular variety at low cost (recolours, clothing, helmets/hats, weapons, magic on shared bodies); every enemy goes through it; judged in motion at fixed checkpoints; quality between "good enough to test" and Vanillaware; tens of images, not hundreds; for this game first, a reusable skill later if it works. Written as section 0 of `docs/design/rig-standard.md`; the rules below it still need the user's approval.
- 2026-10-16 No sprite sheets for characters (user asked about Golden Axe-style sheets): AI frames drift, every gear/weapon swap would multiply frames, too many images. Short frame sequences only for effects; magic = rig pose + separate effect art + tint.
- 2026-10-16 Rig standard approved by the user (`docs/design/rig-standard.md`): every rigged character follows it. A009 (delivered before approval, from the old packet) is reviewed as the rat's G1 master + first parts; the gaps against the standard go into a follow-up art task.
- 2026-10-16 The two agents are called **Code** (Claude Code, writes the game) and **Art** (Codex, draws the art) in all guides and docs; supersedes "code builder" / "art builder". (User.)
- 2026-10-16 Individual variety for enemies (user asked that three archers not look identical): face-detail overlays that fit every expression, random fur/clothing tints, optional gear picks, small render-only size change. Added to the rig standard (section 7a). Classic beat 'em ups mostly use palette swaps only.
- 2026-10-16 Rat Raider head set **R** (standee head with a slightly longer muzzle and visible front teeth), from A009's review. (User.)
- 2026-10-16 Rig deliveries carry a `rig-source.json` (parts, parents, joint points measured on the shared canvas, draw bands, swaps, overlays); Code's rig bench and importer read it (rig standard section 5).
- 2026-10-16 Scrolling stages: the camera never scrolls back (Golden Axe style); when the stage loops, the player returns to the start (placeholder until a boss or stage exit). (User, from T013.)
- 2026-10-16 Weapons: whenever an enemy drops a weapon, it is the same weapon it was holding (user). The Rat Raider holds the A003 rat cutlass item (the floor weapon), not a separate rig sword; A010's sword drawing is dropped.
- 2026-10-16 A010 rat (head R) look approved (user: "much better, much closer to the standee"); passes G2 and the bench motion strip. Next: A011 finishing set (gear refit, masks, face details) and T018 import.
- 2026-10-16 Clarifies the weapon-drop rule: enemies don't have to drop their weapons (we don't want the floor flooded with weapons); but when one does drop a weapon, it is the same weapon it was holding. (User.)
- 2026-10-16 A011 rat finishing set approved (user: "very cool"). In game, cloth tints default to a muted, earthy palette (lead's call; adjustable in the lab) so varied rats stay in the art bible's world.
- 2026-10-16 Rat walk: upright variant F (hips slightly above the master crouch, torso leaned back, 2.0 steps/s); the idle stays the hunched master crouch. User found the first walk "very scuttly" next to the upright mouse and picked F in game (T018).
- 2026-10-16 The engine supports more than one hero (up to 3) before more content is added: `w.heroes`, per-slot input, enemies target a hero, camera keeps all heroes on screen, game over when all are down. One-player play stays exactly as it was. (User; T021.)
- 2026-10-16 The hook (user): community and helping, in story, home base and combat. A fallen world; one mouse restores a ruined stronghold by rescuing captives on missions; rescued folk move in and become abilities, buffs or fellow adventurers; missions bring gear and rebuilding resources; co-op heroes fight by helping each other. Written into the game brief. Supersedes the open hook question (study 2026-10-15); details (solo allies, mission structure, helping verbs, failure) still open.
- 2026-10-16 Hook details (user): rescued adventurers fight beside you as **AI allies** (solo and co-op are one game). Not every mission is a rescue, but rescues are part of it. Structure: **go out on a mission, come back home**, then the next (not mission after mission). First helping verbs to build: **picking up a downed friend** and **tossing potions** (T022). What failure costs: later.
- 2026-10-16 New Mouse Fighter (A013) approved, with the turned-out near foot for planted poses (user: "that's correct!"). Replaces the A002/A006 rig in T023.
- 2026-10-16 Home loop (user): avoid the five failures from the study (home timers, currency sprawl, required grind, chores that undercut warmth, missable rescues); all 15 study recommendations accepted; gear may grow over time (lead: start weapon + ring, unlock more slots through rescues, each item one clear effect, visible gear as rig overlays). Co-op players share one abbey. Missions hand-crafted first, procedural later if reliable (build from modular data pieces). Allies can be downed needing a fix at home, never killed except by story (lead proposes wounded = sit out a mission or tended by a rescued healer, not a rare item). Reformed vermin can join. Cast size: too early. Gathered in `docs/design/home-loop.md`.
- 2026-10-16 Standards before content (user): settle how things are built (heroes, enemies, missions) and apply the lessons learned before making more heroes and enemies.
- 2026-10-16 Gear: mostly as the lead proposed; items needn't all be highly significant, but clear, meaningful items are the goal (user). Downed allies: wounded for one mission, or no cost at all; decide by testing (user). Next standard after T022/T023: a combatant standard for heroes and enemies (user agreed).
